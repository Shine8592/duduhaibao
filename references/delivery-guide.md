# 投放规格与注意事项

> 渲染出图只是半成品。**同一张海报投到不同平台**，对格式、体积、尺寸的要求不同：
> 平台会二次压缩、有单张体积上限、有的还会裁切。先看表再投。
>
> 一键生成投放包：`./build.sh --pack`（或 `.\build.ps1 -Pack`）→ 产出 `dist/<日期>/`。
> 包里的 `web/` 是**已转好的 RGB JPEG**（平台多会重压 PNG，先转更稳），
> `manifest.json` 记录了每个文件的尺寸 / 字节 / sha256 / 建议投放。

## 一、平台投放速查

| 平台 / 渠道 | 建议用包里的 | 尺寸 | 单张上限（近似）| 说明 |
|---|---|---|---|---|
| 微信公众号（正文图）| `web/poster-social.jpg` 或 `poster-square.jpg` | 3:4 / 1:1 | ~10 MB | 上传后平台会再压缩，JPEG 更稳 |
| 公众号首图 | `web/poster-square.jpg` / `poster-wide.jpg` | 1:1 / 16:9 | ~10 MB | 首图会被裁切，主体压中心区 |
| 小红书 | `web/poster-social.jpg` | 3:4 | ~20 MB | 竖图信息流展示最佳 |
| 抖音 / 视频号 / 快手 / IG Story | `web/poster-story.jpg` | 9:16 | ~10 MB | 底部 ~15% 被 UI 遮挡（已由闸门保证）|
| 微博 / 知乎配图 | `web/poster-wide.jpg` | 16:9 | — | — |
| 朋友圈 | `web/poster-social.jpg` | 3:4 | 建议 < 1 MB | 朋友圈压缩最狠；信息流会缩成方形裁切 |
| Open Graph（FB/LinkedIn）| `web/poster-wide.jpg` | ~1.91:1 | ~8 MB | 需要精确 1200×630 时另做模板 |
| X / Twitter 大图卡 | `web/poster-wide.jpg` | ~1.91:1 | ~5 MB | — |
| 印刷 / 张贴 | `print/poster-a4.pdf`（矢量）| A4 | — | 优先 PDF；PNG 为 300dpi 备份 |
| 易拉宝 / 展架 | `print/poster-banner.pdf` | 80×200cm | — | 底部 ~30cm 会被展架遮挡 |

> 上限是**近似值**，平台会调整；投前若不确定，用 `manifest.json` 里的字节数与上表核对。

## 二、印前检查（print/）

- [ ] A4 页边距 ≥ 18mm；外框离页边 ≥ 10mm（家用打印机有不可打印边）
- [ ] 易拉宝底部 ~30cm 不放关键信息（展架底脚遮挡）
- [ ] 交付**矢量 PDF**（`typst` 原生输出，字体已嵌入），不是位图
- [ ] 若有背景图/出血需求，另行扩展画布（本仓示例未做出血）

## 三、扫码检查（所有含二维码的成品）

- [ ] 用**成品**解码一次，确认可扫且内容正确：`python example/tests/check_qr.py`
- [ ] 二维码静默区 ≥ 4 模块；尺寸不要小于约 20mm（印刷）/ 25% 画幅（屏幕）

## 四、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 上传后糊了 | 平台二次压缩 PNG | 用包里的 `web/*.jpg`（已 RGB + 质量 88）|
| 图被拒 / 传不上 | 超过单张上限 | 用同目录的 `*.compressed.jpg`（质量 70）|
| 首图主体被切 | 平台按 1:1 裁切 16:9 图 | 用 `poster-square`，或把主体压中心区 |
| 竖屏底部信息看不见 | 落进平台 UI 遮挡区 | 用 `poster-story`（安全区已由 preflight 闸门保证）|
| 打印边缘被裁 | 无不可打印边留白 | 见「印前检查」|
| 中文变方块 | 目标机器无中文字体 | 交付成品图（PNG/PDF）而非可编辑源；PDF 字体已嵌入 |
