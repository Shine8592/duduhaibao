## 一、机器可验（🔒 跑一遍就能过）

```bash
cd example
python tests/run_tests.py        # 断言/溢出/防误报
./build.sh                       # 渲染 + 预检双闸（数据 + 成品）
python tests/check_qr.py         # 二维码可扫性
./build.sh --pack                # 交付包（含体积预警）
```

- [ ] 🔒 **尺寸正确**：每种格式的产物像素尺寸 == 声明值（`preflight.py` FORMATS）
- [ ] 🔒 **非空白**：墨迹占比 > 0.5%（防渲染失败却"成功"）
- [ ] 🔒 **底部净空干净**：底部安全带纯白（抓内容被静默裁到页面外）
- [ ] 🔒 **编译期断言不误报**：真实配置能过（`ok_all.typ`）
- [ ] 🔒 **历史 bug 仍会大声报错**：`bug_*.typ` 编译失败且信息含关键字
- [ ] 🔒 **二维码可扫**：从**成品**里解码，内容与源图一致，且全图只有一个
- [ ] 🔒 **字体可用**：`typst fonts` 命中字体栈里的至少一款
- [ ] 🔒 **风格合法**：`--input style=` 的名字在 `lib/styles.typ` 中存在
- [ ] 🔒 **对比度达标**：逐套配色算 WCAG（正文/小字 ≥ 4.5，大字 ≥ 3.0）——`preflight.py` 已做成闸门
- [ ] 🔒 **环境自检**：`python scripts/doctor.py` 必需项齐全
- [ ] 🔒 **体积不超平台上限**：`--pack` 会对超限文件预警并出压缩版（见 `delivery-guide.md`）

## 二、人眼判断（👁 不能自动化的部分）

### 版式
- [ ] 👁 页边距符合物理常识：A4 ≥ 18mm；易拉宝底部 ~30cm 不放关键信息
- [ ] 👁 各栏底部大致对齐，没有突兀的空白块或挤压块
- [ ] 👁 文字无重叠、无裁切；强调线/色块都在文字**下层**
- [ ] 👁 **紧跟标题的强调线/分隔线用流式间距**（同一 block 内 `#v()`），**不用硬编码 `dy`** ——
      硬编码的 dy 隐含假设了标题行数，标题一旦变 2 行，线就落到字底上（静默 bug，
      见 `poster-social.typ` 的注释与 v2.1.1 修复）
- [ ] 👁 层次清楚：一眼能分出标题 → 亮点 → 信息 → 报名
- [ ] 👁 缩略图（`out/*_preview.jpg`）在手机上也能读清主标题
- [ ] 👁 **关键信息避开平台安全区**（底部按钮/标题栏遮挡；见 `references/platform-specs.md`）
- [ ] 👁 **可爱/节气/照片**三个场景额外看：可爱版圆角与圆体是否生效；节气**日期**是否与 `solar_terms.py` 一致；照片是否被 `cover` 裁掉了主体

### 内容（来自源头，不看图猜）
- [ ] 👁 标题、日期、价格、机构名逐字核对**源数据**，不是看图读出来的
- [ ] 👁 日期星期由 stdlib 计算并断言（`references/calendar-and-date-grids.md`）
- [ ] 👁 亮点条数 3–4 条，没有把版面挤爆
- [ ] 👁 没有残留占位符（`示例` / `TODO` / `draft: true` 已改 false）

### 风格
- [ ] 👁 配色与活动调性匹配（正式活动别用高饱和跳色，反之亦然）
- [ ] 👁 同一活动跨格式配色一致（都基于同一 `--input style=`）
- [ ] 👁 对比度：次要文字（muted）在白底上仍可读
- [ ] 👁 只有两种字族；中文无豆腐块、英文数字无乱码

## 三、反"通用 AI 观感"（👁 借用 victor-design / design-poster 的纪律）

生成式设计最常见的"AI 味"，交付前逐条排查：

- [ ] 👁 **不要把"专业"等同于电影感 / 深色 / 强对比 / 高密度**
- [ ] 👁 没有无意义的装饰：随机光斑、无来由的渐变、AI 风格的"科技线条"
- [ ] 👁 文案没有 AI 腔（"赋能""闭环""全新升级"堆叠）——写人话
- [ ] 👁 标题不自动断行产生孤字（断行写进**内容**，见 `SKILL.md` 铁律）
- [ ] 👁 图标/emoji 真的渲染出来了（不是豆腐块）
- [ ] 👁 配色克制：主色 + 一个点缀即可，不要彩虹

## 四、交付话术

- [ ] 报**具体尺寸**与文件路径（可核验的交付证据）
- [ ] 说明改了哪些、**没动**哪些（尤其改图场景）
- [ ] 有残余瑕疵就如实说明，并给出后续处理建议——不要为了"完美"压着不发
