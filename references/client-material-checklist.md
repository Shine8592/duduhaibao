# 客户物料交付前 · 信息完整度与合规清单

> 4.4.0 新增。依据：三次真实海报任务复盘 —— 某保险客户活动海报交付时，
> 「石化支行是否写全称 / 报名方式 / 合规审核」三项在消息末尾「顺便提一句」，
> 用户未答复就照原样交付了。对保险/银行类客户物料，这三项任一缺失都是硬伤：
> 集合点简称→客户找不到地方；无报名方式→海报白印；未过合规→公司层面拒收。
>
> **定位**：这不是「建议看一眼」，是**阻断项**。P0 缺任意一条，不得直接交付成品。

## 硬规则

1. 交付前逐项过下表，P0 项**每一条**都要有结论（有 / 无 / 不适用 + 依据）。
2. **P0 缺任意一条 → 必须先问用户**。用户明确说「就这样 / 不用补」才放行，
   并在交付消息里**记录该答复原文**（例如「用户 11-04 明确：集合点保留简称，不补」）。
3. 把结论写进交付消息，不是只写在心里。清单结论可机器复核。

## 信息完整度

| 检查项 | 缺失后果 | 阻断级别 |
|---|---|---|
| 完整机构名（非简称） | 客户找不到集合点 | **P0 阻断** |
| 活动日期 + 星期 + 年份 | 跨年误读 | **P0 阻断** |
| 完整地址（到园区 / 门牌 / 楼层） | 导航失败 | **P0 阻断** |
| 报名方式（电话 / 二维码 / 客户经理） | 无法转化，海报白印 | **P0 阻断** |
| 主办方署名 + 落款 | 合规风险 | **P0 阻断** |
| 集合时间早于出发时间的提前量 | 迟到纠纷 | P1 |
| 保险 / 银行类：收益承诺用语 | 监管红线 | **P0 阻断** |

### 执行方式

- 机构名、地址、日期这些「有意义的字符串」**从数据源核对**（`lib/data.typ` / 文案原文 /
  `date` 命令），**不要从渲染图 OCR 回读** —— 视觉/ OCR 会把 `2026` 读成 `2024`、
  把简称读成全称（技能的既有铁律：「Never let the model produce a date」）。
- 二维码若承担报名入口，按既有规则从**最终成品图**解码验证（quiet zone ≥ 4 module），
  不能只在源文件里看。
- 星期用 stdlib 算（`datetime.weekday()`），不让模型猜。

## 行业合规（保险 / 银行 / 基金客户物料）

触发条件：客户属金融、保险、银行、券商、基金，或物料涉及产品 / 收益 / 客户活动。

| 检查项 | 要求 |
|---|---|
| 收益承诺 | **不得出现**「保本」「稳赚」「保证收益」「零风险」「必涨」等承诺性表述 |
| 公司名称 | 必须用**工商全称**（例：`某某人寿保险股份有限公司`），不用简称、不用品牌昵称 |
| 产品提示 | 涉及产品的，标注「投资有风险」类风险提示 |
| 合规过目 | 建议交付前由用户方合规过目，并在交付消息里**显式提醒一次** |
| AI 水印 | 底稿若来自生图模型，放大右下角查半透明描边水印（见 illustration-set-posters.md §0），**不能带水印交付** |

> 合规提醒是「显式提醒一次」，不反复劝说；用户说已过合规 / 不用审，接受即可。
> 但「不得出现收益承诺」和「公司全称」是监管红线，不因用户一句话放行 —— 发现就指出。
